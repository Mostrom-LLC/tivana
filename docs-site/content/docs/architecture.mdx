## System Overview

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   Browser    │────►│   Runtime    │────►│    Agent     │
│  (Chromium)  │◄────│  (tivana)    │◄────│   (LLM/AI)   │
└──────────────┘     └──────────────┘     └──────────────┘
       │                    │                    │
       │                    │                    │
   Renders page        Streams state        Reasons about
   Executes actions    Routes actions       what to do
```

## Components

### 1. Browser

- Chromium-based (Chrome, Edge, Brave, Arc)
- Visible window — agent actions are observable in real-time
- Connected to the runtime via CDP (Chrome DevTools Protocol)

### 2. Runtime (tivana)

- Rust process, communicates with agents via WebSocket
- Connects to the browser via CDP
- Reads accessibility tree, computed styles, layout rects
- Streams page state and events to agents
- Executes agent actions (click, type, navigate, scroll)
- Manages observation lifecycle (mutation observer, page events)

### 3. Agent

- Any AI system that can receive JSON and output actions
- Receives streaming page events (mutations, navigation, focus, scroll)
- Requests full snapshots when it needs complete state
- Reasons about what to do based on goal + perception
- Sends actions back to runtime

## Browser Transports

The runtime supports two ways to connect to Chromium.

### Managed Browser (default)

The runtime launches its own Chromium process with remote debugging enabled.

```
Runtime ──── launches ────► Chromium (--remote-debugging-port)
   │                             │
   └─────── CDP ────────────────┘
```

- Runtime controls the browser lifecycle
- Isolated environment per session
- Best for headless or automated workflows

### Extension-Backed Session

The Tivana Chrome Extension connects the runtime to an existing browser tab via the `chrome.debugger` API.

```
User's Chrome ◄──── chrome.debugger (CDP 1.3) ────► Extension
                                                        │
                                                   WebSocket
                                                        │
                                                    Runtime
```

- Uses the user's real browser profile (cookies, login state, trust score)
- Human-observable — agent operates in a tab the user can see
- Extension connects to runtime via WebSocket, translates commands to `chrome.debugger` CDP calls
- Extension is a Manifest V3 service worker with auto-reconnect

**When to use which:**

| Transport | Use case |
|-----------|----------|
| Managed browser | Automated/headless tasks, isolated sessions, CI |
| Extension | Tasks requiring user's login state, human-observed browsing, sites with bot detection |

Both transports expose the same perception and action API to agents. The agent does not need to know which transport is in use.

## Observation Flow

```
Agent                    Runtime                  Browser
  │                        │                        │
  │── perceive.observe ──►│                        │
  │                        │── inject listeners ──►│
  │                        │── MutationObserver ──►│
  │                        │                        │
  │◄── page.loaded ────────│◄── DOMContentLoaded ──│
  │◄── page.mutation ──────│◄── MutationObserver ──│
  │◄── page.focus ─────────│◄── focusin ───────────│
  │◄── page.scroll ────────│◄── scroll (200ms) ────│
  │◄── page.navigated ─────│◄── popstate/push ─────│
  │◄── page.resize ────────│◄── resize ────────────│
  │                        │                        │
  │── perceive.elements ──►│                        │
  │◄── [full snapshot] ────│                        │
  │                        │                        │
  │── act.click("e5") ────►│                        │
  │                        │── CDP dispatch ───────►│
  │◄── page.mutation ──────│◄── DOM changed ────────│
```

The key distinction:
- **Snapshots** are request/response — the agent asks, the runtime answers with full state
- **Events** are server-push — the runtime streams changes as they happen

**Recovery path**: If the agent reconnects or suspects missed events, it requests a full snapshot (`perceive.pageState` + `perceive.elements`) and re-starts observation with `perceive.observe`. Events carry IDs and deltas — not full element data — so the agent must maintain its own state model by applying incremental events on top of the last snapshot.

See [observation-guide.md](observation-guide.md) for the full observation model.

## Design Principles

1. **Perception is the product.** Actions exist to support perception-driven agency.
2. **The agent reasons.** Tivana provides structured awareness; the agent decides what to do.
3. **Human-observable.** Agent actions happen in a visible browser — nothing is hidden.
4. **Transport-agnostic API.** Managed browser and extension sessions expose the same interface.
5. **Streaming by default.** Observation is continuous, not polling-based.
